Here is the finalized, definitive tech stack to conclude the architectural planning phase and meet all assignment constraints with top-tier tools.

### **Frontend (Client-Side)**

* **Framework:** Next.js (App Router) utilizing TypeScript.
* **Styling Engine:** Tailwind CSS.
* **Component Library:** shadcn/ui (for rapid, accessible, and highly customizable UI elements matching the Fireflies aesthetic).
* **State Management:** Zustand (perfect for handling the bidirectional media-player-to-transcript sync state efficiently).
* **Icons:** Lucide React.
* **Media Handling:** Native HTML5 `<audio>`/`<video>` API integrated via React `useRef` hooks.

### **Backend (Server-Side)**

* **Framework:** FastAPI (Python).
* **ASGI Server:** Uvicorn.
* **Data Validation & Serialization:** Pydantic.
* **ORM (Object Relational Mapper):** SQLAlchemy.

### **Database & Search**

* **Primary Database:** SQLite.
* **Global Search Implementation:** SQLite FTS5 (Full-Text Search extension). This provides lightning-fast text matching natively within SQLite without needing external dependencies like Whoosh or Elasticsearch.

### **AI & LLM Services**

* **LLM API:** Groq.
* **Model Recommendation:** Utilize a fast Groq-hosted model (like `llama3-8b-8192` or `mixtral-8x7b-32768`) to handle the AI Summary generation, action item extraction, key topics formatting, and the bonus "ask a question about this meeting" chat feature with zero latency.

### **Utilities (Export Features)**

* **PDF Export:** `fpdf2` (Python library for generating PDF transcripts/summaries).
* **Markdown/TXT Export:** Standard Python file I/O (`.write()`).

### **Phase 2: Database Schema & Backend Core**

**Objective:** Build the well-structured SQLite schema and API endpoints with proper separation of concerns.

* **Database Models (SQLAlchemy):**
* `User`: ID, Name, Email, Avatar.
* 
`Meeting`: ID, Title, Date, Duration, Media URL (placeholder audio/video). Ensure data persists reliably.


* 
`Participant`: Junction table linking `User` and `Meeting`.


* 
`TranscriptSegment`: ID, MeetingID, SpeakerName, StartTime, EndTime, TextContent.


* 
`Summary`: ID, MeetingID, OverviewText, KeyTopics (JSON array).


* 
`ActionItem`: ID, MeetingID, Description, IsCompleted.


* 
`Tag`: ID, Name.


* 
`Comment`: ID, SegmentID, UserID, Text (for highlights/soundbites).




* 
**Global Search Enablement:** Implement SQLite FTS5 (Full-Text Search) on the `TranscriptSegment` and `Meeting` tables to power the global search across all meetings.


* **API Endpoints (FastAPI):**
* 
`POST /meetings`: Create a meeting via file upload (.txt/.json) or manual form entry.


* 
`GET /meetings`: Retrieve the list of past meetings.


* 
`PUT /meetings/{id}` & `DELETE /meetings/{id}`: Edit meeting metadata (title, participants) and delete meetings.


* `GET /meetings/{id}/details`: Fetch transcript, summary, and action items in a single optimized payload.
* 
`POST /action-items`, `PUT /action-items/{id}`: Add, edit, and complete action items.
